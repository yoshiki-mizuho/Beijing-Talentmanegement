# ほかの Hub とやり取りする

## 読む資料

- `contract/guide.md` §12（置き場所 §12.1、口の出し方 §12.2、してはいけないこと §12.3、一覧と調べる順 §12.4）
- 口を出すときは、`contract/hubs/FORMAT.md`（書式。基盤から取った写し）

## ほかの Hub の情報を使う

1. 作る前に一覧を見る: `scripts/hub-contracts.sh`。相手が決まったら `scripts/hub-contracts.sh <相手の製品名>`。
2. 一覧での状態ごとにすることは、§12.4 の「調べる順」の表のとおり。口が無い・予定だけのときは、回り道（§12.3）を作らず、相手の口なしでも動く形にして、人に伝える。
3. 使うと決めた定義だけを取り込む: `scripts/hub-contracts.sh <相手の製品名> --take`。`contract/hubs/<相手の製品名>/` は書き換えない。コードは、取り込んだ定義から作る（コマンドは `CLAUDE.md` の「この Hub の決まり」）。
4. 呼ぶのはサーバ同士。テナントの渡し方は §12.2。
5. 通信を開けるには、基盤のリポジトリの一覧ファイルの変更が要る（§12.2）。人に伝える。

## 自分の口を出す・予定する

1. 基盤に寄せる情報か、自分が持ち主の情報かを決める（§12.1）。
2. `contract-out/README.md`（人が読む説明）と `contract-out/hub.yaml`（要約。予定だけなら状態を予定にして issue を書く）を、`FORMAT.md` の書式で書く。定義は `contract-out/proto/` に置く。
3. 出すメソッドは、渡してよい読み取りだけにする。ポートの分け方、テナントの扱い、互換は §12.2。
4. 定義を変えたら、`hub.yaml` の版を上げる。タグ（`FORMAT.md` の「版とタグ」）は人に頼む。
5. `main` に入ると、基盤の CI が集めて一覧に載せる（§12.4）。`scripts/hub-contracts.sh` を流し、「集めた結果」の表で、自分の Hub が「読めた」になっていることを確かめる。ほかの状態なら、同じ行の「Hub の側ですること」を行う（人に頼むものは伝える）。

## 確かめること

- 使う側: 一覧を実際に流して、状態を見てから作った。相手の DB・内部の API・ブラウザの中継を使っていない
- 出す側: `contract-out/hub.yaml` が `FORMAT.md` の必須の項目を満たし、製品名が `CLAUDE.md` の製品名と同じ
- 人に頼むこと（通信を開ける、タグ、issue）を、漏れなく伝えた
