# デザインガイドライン（TalentHub）

## 目的

TalentHub の画面の見た目と振る舞いの決まり。Codex へのタスク指示書では、この文書の該当する節を「仕様」として参照する。

TalentHub は Hub シリーズの製品 `talenthub` として、基盤の上で動く。見た目の共通の決まりは基盤が `contract/design/` で配っていて、そちらを正とする。この文書は、基盤の決まりの読み方と、TalentHub だけの決まり（主の色、画面ごとの決まり、バッジ、文言）を書く。

| 読むもの | 中身 |
| --- | --- |
| `contract/design/README.md` | 守ること・自由なこと、主の色、文言と振る舞い |
| `contract/design/tokens.css` | 色・文字・余白・角・影・寸法の変数（`--hub-*`） |
| `contract/design/layout.md` | ヘッダ、左のナビ、本体、狭い画面 |
| `contract/design/components.md` | ボタン、入力欄、カード、バッジ、表、空の状態、読み込み中、トースト、ダイアログ |
| `contract/design/example.html` | 枠と部品を素の HTML と CSS で組んだ見本 |

`contract/` は基盤の持ち物なので書き換えない。値が足りないときは、Hub の側で値を作らず、基盤のリポジトリに issue を出す（人が出す）。

## 基本方針

- 共通の決まりに合わせ、ほかの Hub（ReportHub、TaskHub など）と同じ製品群に見えるようにする。製品を見分ける手がかりは、主の色と、ヘッダの製品の印と名前。
- スキル評価は人事に関わるため、キャラクター育成などの遊びの要素は入れない。ドット絵のバッジと、レベルアップ・ロール達成の知らせは残すが、動きで目を引かず、事実を落ち着いて伝える。
- 本人の前進に焦点を当てる。数値で他人と比べて評価する表現は避ける。
- ダークモードは作らない。

## 値の書き方

- 色・文字・余白・角・影・寸法は `var(--hub-...)` で書く。Tailwind では `bg-[var(--hub-color-surface)]`、`text-[length:var(--hub-text-sm)]` の形にする。
- `src/app/globals.css` のアプリの古い変数（`--primary`、`--muted-foreground`、`--border` など）は、`--hub-*` を指す別名として残している。新しく書くコードでは `--hub-*` を直接使う。
- Tailwind の色の名前（`bg-amber-50`、`text-slate-700` など）と、16 進の色を書かない。例外は下の「Hub が決める色」だけ。
- 意味で色を選ぶ。成功は success、注意は warning、危険は danger、情報は info、どれでもないものは neutral。

## 主の色（えんじ色）

TaskHub が緑を使っているため、TalentHub の主の色はえんじ色にする（2026-11-22 決定）。`src/app/globals.css` で、`tokens.css` の後に 11 段を上書きしている。上書きしてよいのは `--hub-color-primary-50`〜`950` と `--hub-color-text-on-primary` だけ。

| 段 | 値 | 目安 |
| --- | --- | --- |
| 50 | `oklch(0.965 0.016 20.7)` | 選択中の地 |
| 100〜400 | `oklch(0.93 0.034 20.7)`〜`oklch(0.67 0.130 20.7)` | 淡い地、段階の色 |
| 500 | `oklch(0.56 0.145 20.7)` | フォーカスの輪 |
| 600 | `oklch(0.47 0.145 20.7)` | 主ボタン、リンク（白い文字との比 7.37） |
| 700 | `oklch(0.41 0.130 20.7)` | ホバー、選択中の文字 |
| 800〜950 | `oklch(0.36 0.115 20.7)`〜`oklch(0.23 0.065 20.7)` | 濃い文字 |

- 基盤の危険の色（`--hub-color-danger`）は鮮やかな赤で、えんじ色と同じ赤系。主の色より明るく鮮やかなので見分けはつくが、危険の操作は色だけに頼らず、文言（「削除」「差し戻す」）とアイコンでも分かるようにする。
- 色だけで状態を区別しない。文字、アイコン、形を併用する。

## Hub が決める色

基盤に変数の無い場面は、Hub が値を決める（`contract/design/README.md`）。値は 1 か所にまとめ、何の色かを注釈で書く。

| 場面 | 置き場所 | 決まり |
| --- | --- | --- |
| グラフの系列 | `src/shared/ui/chart-colors.ts` | 1 番目は主の色（600 と同じ値）、2 番目は青（基盤に変数が無い。えんじ色・危険の色と見分けやすい）、3 番目からは warning・success・neutral の文字の色と同じ値。グラフの部品には色を値で渡すため、ここだけ値で書き、そばに「どの変数と同じ値か」を注釈で書く |
| スキルのレベルの段階 | `skill-level-style.ts`、`skill-map-tiles.tsx`（`src/modules/skill-map/presentation/`） | 主の色の 50 / 100 / 200 / 600 / 800 で、Lv1 が淡く Lv5 が濃い。文字と地の比は 4.5:1 以上（今は 7:1 以上） |
| 頭文字のアバターの地 | `src/shared/ui/member-avatar.tsx` | 基盤のアバターが無い人だけ。基盤の `avatarColor` の色名を、意味の近い基盤の色（primary・info・warning・success・danger・neutral）に割り当てる |
| ドット絵のバッジ | `src/modules/growth/domain/badge-art.ts` | 絵の色。レア度の枠の色を含めて、絵として扱う |

## レイアウト

`contract/design/layout.md` のとおり。TalentHub が決めている中身は次のとおり。

| 要素 | TalentHub の中身 |
| --- | --- |
| ヘッダ（高さ 60px、class `hub-header`） | 左に製品の印「T」と「TalentHub」。右に、はじめの3ステップの進み具合、主要ボタン、通知、本人のメニュー |
| 主要ボタン | ロールごとに最もよく使う操作を置く。MEMBER は「スキルを申請」、MANAGER と ADMIN は「承認待ち N件」。幅 1024px 以上で表示する |
| はじめの3ステップ | 「はじめの3ステップ N / 3」と進み具合の帯。狭い画面では「N/3」に縮める。すべて済んだら出さない |
| 本人のメニュー | 氏名、メール、スキルプロフィール、ログアウト。ログアウトは基盤の `POST /api/v1/auth/logout` の後に `/login` へ移る |
| 左のナビ（幅 56px） | アイコンだけ。項目の名前はツールチップと `aria-label`。ロールで見える項目が変わる（`src/shared/auth/app-access.ts`） |
| 下のナビ（幅 1024px 未満） | ロールごとに主な 3〜4 項目と「そのほか」。MEMBER は通知も置く |

| 個人・チーム・組織の切り替え | ダッシュボードの右上に置く。チームと組織は MANAGER と ADMIN だけが使える |

## 部品

見た目は `contract/design/components.md` のとおりに `src/shared/ui/` で作る。TalentHub だけの決まりは次のとおり。

| 部品 | 決まり |
| --- | --- |
| リアクション | アイコンと件数だけを表示し、文字はツールチップで示す。種類は、おめでとう（クラッカー）、すごい（星）、教えてほしい（吹き出しに？）の3つ。押すと選択中の地（`--hub-color-selected-bg`）に変わる。`aria-label` と `aria-pressed` を付ける |
| ツールチップ | ホバーとキーボードのフォーカスの両方で表示する。タッチの環境では、ほかの場所にも同じ情報を出す |
| トースト | 操作の結果（成功・失敗）は必ずトーストで知らせる。成功の文言では、次に何が起きるかも伝える（例：「2件を申請しました。マネージャーの承認をお待ちください。」） |
| 確かめのダイアログ | 1件の日常の操作は確かめずに結果をトーストで知らせる。複数件をまとめて確定する操作と取り消せない削除は確かめる。差し戻しは理由の入力を必須にする |
| 新着・未読の印 | 小さな点か件数の丸（`--hub-color-badge-dot`）。文字のバッジを足さない |

## 動き

`contract/design/README.md` の「動き」に従う。動かすのは、読み込み中の表示（スケルトンの濃さ、ボタンの輪）と、色の変わり目だけ。

- 紙吹雪、波紋、明滅、ふくらむ・はねる動きは使わない。
- スケルトンの動きは `--hub-skeleton-duration` / `--hub-skeleton-ease`。`prefers-reduced-motion` のときは止める。

## 主要画面の決まり

### スキル申請

- 全スキルをカテゴリごとに一覧で表示し、各行に Lv1〜5 のボタン（44×44px）を並べる。
- 今のレベルを淡い色で示し、変えた行は左端に主の色の線を引いて地を選択中の色にする。
- 選んだレベルの定義（スキルのレベルの説明）を、同じ行に表示する。
- 承認待ちのスキルは選べないようにし、その理由を表示する。
- 検索、「すべて／未保有のみ／変更した行」の絞り込み、画面の下に固定した「N件を申請」と「取り消す」の帯を置く。

### スキル承認

- 待ち日数の長い順に並べる。5日以上待っているものは注意（warning）のバッジで示す。
- 各行に、今のレベル → 申請されたレベル、経験年数、申請日を表示する。
- チェックボックスで複数を選んで一括で承認できる。「補正」はレベルを選び直して承認する。「差し戻し」は理由の入力を必須にする。

### レベルアップとロール達成の知らせ

- 未読の承認の通知（承認、補正承認）があるとき、次に画面を開いた時点でダイアログを表示し、閉じたら既読にする。
- 表示する内容：スキル名、旧レベル → 新レベル、新しいレベルの定義、承認したマネージャーとコメント、目標ロールの進み具合、新しく獲得したバッジ。
- ダイアログは `components.md` §9 の形で、普通に開くだけにする。動きは付けない。
- 題は事実を書く（例：「TypeScript が Lv3 になりました」「フロントエンドエンジニアを達成しました」）。英語の飾り（「LEVEL UP」など）は使わない。
- ロールを達成したら、続けて次の目標ロールを選べる。「あとで決める」も選べる。

### ダッシュボード

- 個人の表示：目標ロールの進み具合、達成バッジ、カテゴリ別のレーダーチャート、成長カレンダー、成長の記録、チームのレベルアップ、教えてもらえそうな人。
- チームの表示（自分の部下が対象）：承認待ち、今月のレベルアップ数、ロールの達成者数、目標ロールの設定率、あと一歩のメンバー、しばらく申請のない部下、チームのレベルアップ、チームで不足しているスキル。
- 「応援する」：文面案を編集して、本人に通知を送る。任意で「教えてもらえそうな人」を紹介として添えられる。応援した記録を残し、本人のダッシュボードに「○○さんが応援しています」というカードを出す。
- 「1on1 メモに追加」：マネージャーだけが見られる、部下ごとの話題のリストに足す。メンバー詳細の「1on1 メモ」タブで確かめ、「話した」の印を付けられる。

## 達成バッジ

12×12 のドット絵（1マス4px、表示は64×64pxの枠）で作る。レア度は枠の色で表す（コモン、レア、エピック、レジェンド）。未獲得のバッジは灰色の影絵と点線の枠で表示する。絵の色は「Hub が決める色」として `badge-art.ts` にまとめている。

| バッジ | レア度 | 獲得条件 | モチーフ |
| --- | --- | --- | --- |
| Hello, World | コモン | はじめてスキルを申請した | ターミナルと `>_` |
| セーブポイント | コモン | スキルを5件登録した | フロッピーディスク |
| Lv4 アンロック | レア | はじめて Lv4 に到達した | 4 の入った盾 |
| 連続ビルド成功 | レア | 3か月連続でレベルアップした | 炎 |
| デプロイ完了 | エピック | 目標ロールを達成した | ロケット |
| フルスタック | エピック | スキルを10件登録した | サーバーラック |
| マスター | レジェンド | はじめて Lv5 に到達した | 王冠 |
| ラバーダック | レジェンド | 応援で「教えてもらえそうな人」として3人に紹介された | ラバーダック |
| 1周年 | コモン | 登録から1年たち、その1年に1回以上レベルアップした | ケーキ |
| 一番乗り | レア | まだだれも持っていないスキルを、最初に身につけた | 旗 |
| リトライ成功 | レア | 差し戻されたスキルで、あとから承認された | 回る矢印 |
| コンボ10 | レア | レベルアップが通算10回になった | 「10」 |
| 土台づくり | レア | 前提スキルをすべて Lv3 以上にしてから、その上のスキルを申請した | レンガの積み上げ |
| マルチクラス | エピック | 3つの大分類でレベルアップした | 3色のブロック |
| 拍手 | コモン | リアクションを10回送った | 手と光 |
| 応援団 | コモン | 3人に応援を送った | メガホン |
| 引っ張りだこ | レア | 「教えてほしい」のリアクションを5回もらった（同じ人は1回） | たこ |
| 年越しデプロイ（シークレット） | エピック | 1月にレベルアップした | 初日の出 |
| おかえり（シークレット） | レア | 半年以上あいたあとに、レベルアップした | 家 |

- バッジは DB に保存せず、保有スキル、承認履歴、応援、リアクションから都度計算する。人との比較、申請の数、速さを条件にしない。
- 成長・つながり・シークレットに分け、全部のバッジはプロフィールのバッジ欄で見せる。個人ダッシュボードは「最近とったバッジ」3つと「次に取れそう」2つだけにして、数が増えても高さを変えない。
- 未獲得のバッジの進み具合（「あと1人」など）は本人だけに見せる。未獲得のシークレットは「？」の絵と「？？？」にし、条件を出さない。
- 詳細には名前、レア度、条件、獲得日を表示する。

## 文言

`contract/design/README.md` の「文言」に従い、ビジネスニュートラルにする。あおる言い方・なれなれしい言い方をしない。

- 画面の表記は日本語にそろえる。英語の飾り（「LEVEL UP」「People Intelligence」など）は使わない。
- 状態のコード（ACTIVE など）は、そのまま表示しない。
- 補足の説明は短くし、見出し・アイコン・ツールチップで伝える。
- 感嘆符（！）は使わない。説教調・命令調も避ける。
- 空の状態（データが0件のとき）では、次に取れる行動を示す（例：「承認待ちはありません。」の下に、関係する画面への操作）。空の部品は出さず、何をすれば表示されるかを書く。

## アクセシビリティ

- 操作できる要素は、`button`、`a`、`input` で作る。`div` にクリックの処理を付けない。
- アイコンだけのボタンには `aria-label` を付ける。選択の状態は `aria-pressed` で示す。
- タッチ操作の対象は44px以上にする。
- フォーカスは輪（`--hub-color-focus`）で示す。
- 動きは `prefers-reduced-motion` に従う。

## 基盤のアバター

メンバーのアイコンは基盤の `avatarUrl` をそのまま表示し、画像が無い場合は氏名の頭文字と `avatarColor` で表示する。TalentHub の中で画像をアップロード・削除せず、プロフィールの公開設定による出し分けもしない。
