# デザインガイドライン（TalentHub）

## 目的

このドキュメントは、Phase 4.7 以降の画面設計と実装で守る見た目と振る舞いのルールを定義するものです。

2026-10-09 にプロトタイプのレビューで合意した内容を正とします。Codex へのタスク指示書では、このドキュメントの該当する節を「仕様」として参照してください。

- プロトタイプ：https://claude.ai/artifact/Fy9nM47N4onf8QyFGLA4BD （限定共有。5画面：メンバーのダッシュボード、スキルシート申請、レベルアップ演出、スキル承認、チームのダッシュボード）

## 基本方針

- システム名は **TalentHub** とする。社内の日報アプリ ReportHub と並べて使うことを想定し、将来は社内ポータルとして統合していける見た目にする。
- **レイアウトと部品の型は ReportHub に揃え、配色はティールで独自性を出す。** 社内のユーザーが、操作に迷わず使えることを優先する。
- スキル評価は人事に関わるため、キャラクター育成などの遊びの要素は入れない。ただし、エンジニアが嬉しくなる演出（ドット絵のバッジ、レベルアップ演出）は積極的に使う。
- 成長を肯定する文言を使う。数値で他人と比べて評価する表現は避け、本人の前進と、チームで祝うことに焦点を当てる。

## レイアウト

| 要素 | ルール |
| --- | --- |
| 左のナビゲーション | 幅64pxのアイコンナビ。各アイコンには `aria-label` を付ける。選択中の項目は `--primary` を薄くした背景で示す。スマホでは上部またはドロワーに折りたたむ |
| ヘッダー | 高さ64px。左にロゴと「TalentHub」、中央に検索、右にセットアップの進捗、主要ボタン、通知、アバターを並べる |
| 主要ボタン | ロールごとに最もよく使う操作を、常にヘッダーに置く。MEMBER は「スキルを申請」、MANAGER は「承認待ち N件」 |
| セットアップの進捗 | 「セットアップ N/M」と進捗バーを表示する。項目はプロフィールの確認、スキルを5件登録、目標ロールの設定など。すべて完了したら表示しない |
| 本文 | 最大幅1100〜1200pxで中央に寄せる。カードの間隔は20px |
| 個人とチームの切り替え | ダッシュボードの右上に、セグメント形式の切り替えを置く。チームの表示は MANAGER と ADMIN だけが使える |

## 配色

既存の `src/app/globals.css` のトークンを基本にする。

| 用途 | トークン（値） |
| --- | --- |
| 主色 | `--primary` #0F766E、ホバー時 #115E59、淡色背景 #E6F4F1 |
| 背景 | `--background` #F4F6F5、カードは #FFFFFF |
| 文字 | 本文 #1E2A2A、補足 #5B6B6A（白背景でコントラスト比 4.5:1 以上） |
| 罫線 | #E3E8E6 |
| 祝福 | アンバー系（#FEF3C7 の背景に #92400E の文字、枠は #F59E0B）。レベルアップとバッジだけに使う |
| 警告 | 待ち日数が長い承認などには、同じアンバー系のバッジを使う |
| 危険 | 差し戻しや削除には #B42318 を使う |

- レベルの濃淡は、レベルが高いほど濃いティールで表す。赤系を高レベルに使わない。
- 色だけで状態を区別しない。テキスト、アイコン、形を併用する。

## 文字

- フォントは Noto Sans JP（400／500／700）。演出の見出しだけ 900 を使う。
- サイズの目安：ページ見出し 26px、カード見出し 15px、本文 14px、補足 12〜13px。

## 部品

| 部品 | ルール |
| --- | --- |
| カード | 白背景、1px の罫線、角丸16px、余白20px |
| チップ形式のフィルタ | 高さ34px、完全な角丸。選択中は濃い背景に白文字 |
| アバター | 円形で、名前の頭文字を表示する。色はメンバーごとに固定する |
| リアクション | **アイコンと件数だけを表示し、文字はツールチップで示す。** 種類は、おめでとう（パーティーのクラッカー）、すごい（星）、教えてほしい（吹き出しに？）の3つ。押すと主色の淡色背景に切り替わる。`aria-label` と `aria-pressed` を付ける |
| ツールチップ | ホバーとキーボードのフォーカスの両方で表示する。タッチ環境では、タップで表示するか、ほかの場所にも同じ情報を出す |
| トースト | 操作の結果（成功・失敗）は必ずトーストで知らせる。成功時の文言では、次に何が起きるかも伝える（例：「2件を申請しました。マネージャーの承認をお待ちください。」） |
| 確認ダイアログ | 削除、無効化、差し戻しの前に表示する。差し戻しは理由の入力を必須にする |

## 主要画面のルール

### スキルシート申請

- 全スキルをカテゴリごとに一覧で表示し、各行に Lv1〜5 のボタン（44×44px）を並べる。
- 現在のレベルを淡い色で示し、変更した行は左端に主色の線を引いて背景を色付けする。
- 選んだレベルの定義（スキルレベルのマスタの説明文）を、同じ行に表示する。
- 承認待ちのスキルは選択できないようにし、その理由を表示する。
- 検索、「すべて／未保有のみ／変更した行」のフィルタ、画面下に固定した「N件を申請」と「取り消す」のバーを置く。

### スキル承認

- 待ち日数の長い順に並べる。5日以上待っているものはアンバー系で強調する。
- 各行に、現在のレベル → 申請されたレベル、経験年数、申請日を表示する。
- チェックボックスで複数を選んで一括承認できるようにする。「補正」ではレベルを選び直して承認する。「差し戻し」は理由の入力を必須にする。

### レベルアップ演出

- 未読の承認通知（承認、補正承認）があるとき、次に画面を開いた時点でモーダルを表示し、表示したら既読にする。
- 表示する内容：「LEVEL UP」のバッジ、スキル名、旧レベル → 新レベル、新しいレベルの定義、マネージャーのコメント、目標ロールの進捗、新しく獲得したバッジ。
- アニメーションはポップ、波紋、紙吹雪を約2.5秒で終える。`prefers-reduced-motion` が有効な環境では動かさず、同じ内容を静的に表示する。

### ダッシュボード

- 個人の表示：目標ロールの進捗リング、達成バッジ、カテゴリ別のレーダーチャート、成長カレンダー、成長の記録、チームのレベルアップ、教えてもらえそうな人。
- チームの表示（自分の部下が対象）：承認待ち、今月のレベルアップ数、ロールの達成者数、目標ロールの設定率、あと一歩のメンバー、しばらく申請のない部下、チームのレベルアップ、チームで不足しているスキル。
- **「応援する」**：文面案を編集して、本人に通知を送る。任意で「教えてもらえそうな人」を紹介として添えられる。応援した記録を残し、本人のダッシュボードに「○○さんが応援しています」というカードを出す。
- **「1on1 メモに追加」**：マネージャーだけが見られる、部下ごとの話題リストに追加する。メンバー詳細の「1on1 メモ」タブで確認し、「話した」チェックを付けられる。

## 達成バッジ

12×12 のドット絵（1マス4px、表示は64×64pxの枠）で作る。レア度は枠の色で表す（コモン：ティール、レア：ブルー、エピック：パープル、レジェンド：ゴールド）。未獲得のバッジはグレーのシルエットと点線の枠で表示する。ドット絵のデータはプロトタイプの `Main.dc.html` を参照する。

| バッジ | レア度 | 獲得条件 | モチーフ |
| --- | --- | --- | --- |
| Hello, World | コモン | はじめてスキルを申請した | ターミナルと `>_` |
| セーブポイント | コモン | スキルを5件登録した | フロッピーディスク |
| Lv4 アンロック | レア | はじめて Lv4 に到達した | 4 の入った盾 |
| 連続ビルド成功 | レア | 3か月連続でレベルアップした | 炎 |
| デプロイ完了 | エピック | 目標ロールを達成した | ロケット |
| フルスタック | エピック | スキルを10件登録した | サーバーラック |
| マスター | レジェンド | はじめて Lv5 に到達した | 王冠 |
| ラバーダック | レジェンド | 「教えてほしい」に応えて3人に教えた | ラバーダック |

- バッジは DB に保存せず、保有スキルと承認履歴から都度計算する。ただし「ラバーダック」は、教えた実績の記録が必要になるので、実装する時点で判定方法を決める。
- ツールチップには名前、レア度、条件、獲得日を表示する。

## 文言

- 画面上の表記は日本語で統一する。英語の飾りラベル（例：「People Intelligence」）は使わない。
- 状態のコード（ACTIVE など）は、そのまま表示しない。
- 励ましの一言を、要所に短く入れる（例：「前回の申請から3週間。小さな前進も、記録すると次の自信になります。」）。説教調や命令調は避ける。
- 空の状態（データが0件のとき）では、次に取れる行動を示す（例：「承認待ちはありません。チームのレベルアップにリアクションを送ってみませんか。」）。

## アクセシビリティ

- 操作できる要素は、`button`、`a`、`input` で実装する。`div` にクリック処理を付けない。
- アイコンだけのボタンには `aria-label` を付ける。選択状態は `aria-pressed` で示す。
- タッチ操作の対象は44px以上にする。
- 動きは `prefers-reduced-motion` に従う。
