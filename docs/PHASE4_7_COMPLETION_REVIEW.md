## 進め方の振り返り

- 実装の前にクリックできるプロトタイプを作り、見た目と操作を合意してから実装した。ログイン、メンバー一覧、スキル・ロール管理、組織ダッシュボード、スキルマップは、プロトタイプで案を比べてから決めた。
- 利用者がデモで全画面を触り、気になった点をまとめて挙げ、Claude が「直す／直さない／後で」に整理してから直す流れを3回繰り返した。
- 2回目のレビューの途中から、R2 の修正 MR は Claude が CI の成功を確認して merge まで行った（デモ環境を実質ステージングとして扱う、利用者の判断）。
- 検証は MR ごとに `npm.cmd run verify`（typecheck、lint、単体テスト、build、migration check）、E2E、`ui:check`（3ロールの画面撮影）で行った。終了時点で単体テスト232件、E2E 28本。

## 発生した問題と対応

| 問題 | 原因 | 対応 |
| --- | --- | --- |
| ダイアログの入力中にフォーカスが抜ける | 共通の Dialog が `onClose` の変化のたびに effect を再実行し、フォーカスを戻していた | `onClose` を ref に持ち、effect は開閉時だけ動かす（!44） |
| スキル管理の名前検索が効かない | React Query の `initialData` を、条件を変えた後の新しいキーにも渡していた | 条件が初期値のときだけ使う（!46） |
| E2E が時々失敗する | 未確認のレベルアップ・応援の演出が残る、一覧の読み込み中に行の位置がずれる | 演出を閉じる共通の処理、名前で1件に絞ってから操作する |
| 開発 PC のメモリ不足（8GB） | Next.js のビルド、E2E、Codex の同時実行 | Codex は1つずつ動かす。重い検証は空きメモリを見てから流す。待機用の裏プロセスは止められることがあるので、ジョブの記録を見て再開する |

## 残課題

- **React #418（表示のずれの警告）**：MEMBER のダッシュボードだけで出る。日付の表示はタイムゾーンを固定しているので原因ではない。React がクライアント側で描き直して回復するため、表示と操作への影響は見えていない。原因の特定には開発サーバーでの調査が必要で、メモリに余裕があるときに行う。
- メンバー詳細でスキルを削除しても、レベルの変更履歴に記録されない（Phase 5 の監査ログで扱う）。
- 「相談する」のチャットへのリンク（`CHAT_LINK_TEMPLATE`）の形式は、社内のチャットツールが決まってから設定する。
- `npm run start` の standalone の警告。
- ローカル DB とデモ DB に、E2E や動作確認で作ったデータが残っている（例：「E2Eスキル-…」「E2Eカテゴリ-…」）。
- R3-B の migration（`20261014120000_add_skill_level_guides`）が、デモ DB に適用されていること（GitLab の手動パイプライン `DEMO_DB_TASK=migrate`）を記録として残す。
