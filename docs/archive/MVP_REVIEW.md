# MVPレビュー

## 目的

このドキュメントは、既存MVPアプリから新システムへ継承するもの、再設計するもの、後続フェーズへ回すものを整理するものです。

MVPは `C:\Users\B010504\Documents\CHOSEN-RYOIKI\bk\CA02_talentmanagement` に存在するNext.jsアプリを確認した内容を前提とします。

## MVPの概要

MVPは、メンバーのスキルを可視化・管理するタレントマネジメントシステムです。

主な特徴は以下です。

- Next.js App Router、TypeScript、Tailwind CSSで構築。
- データ保存はlocalStorage。
- Repositoryパターンでデータアクセス層を抽象化。
- メンバー、スキル、ロール、スキル紐付け、スキルマップ、統計ダッシュボードを実装。
- CSV import/export機能を一部実装。
- OpenAI互換APIを使うAI評価機能とフォールバック評価を実装。

## 継承するもの

| 対象 | 方針 |
| --- | --- |
| 業務コンセプト | メンバーのスキルを可視化し、ロール達成状況を把握する方向性を継承する |
| 主要機能 | メンバー管理、スキル管理、ロール管理、スキル検索、スキルマップ、ダッシュボードを継承する |
| Repositoryパターン | DB実装へ置き換えつつ、データアクセスを抽象化する考え方を継承する |
| スキルレベル管理 | 1から5のレベルで表現する基本方針を継承する |
| ロール達成判定 | 必要スキルと必要レベルの組み合わせで判定する考え方を継承する |
| AI評価の考え方 | メンバーのスキル状況から示唆を出す方向性を継承する |
| CSV活用 | 一括登録・更新の手段としてCSVを継承する |

## 再設計するもの

| 対象 | 再設計方針 |
| --- | --- |
| データ永続化 | localStorageからPostgreSQL + Prismaへ置き換える |
| 画面データ取得 | クライアント中心からServer Components、Route Handlers、Server Actions中心へ寄せる |
| 集計処理 | クライアント集計からDB/API側の集計へ移す |
| CSV import | 即時登録ではなく、プレビュー、検証、差分確認、トランザクション登録を行う |
| AI評価 | APIキー保護、キャッシュ、再評価、利用ログ、失敗時フォールバックを設計する |
| 認証・認可 | Auth.jsとRBACを導入し、画面/APIの両方で制御する |
| 監査ログ | 作成、更新、削除、import、AI評価などの操作履歴を記録する |
| UIコンポーネント | shadcn/uiとlucide-reactを使い、UI部品を標準化する |

## 本番コードへ持ち込まないもの

- localStorageを本番データストアとして使う実装。
- 画面コンポーネントから永続化処理へ直接依存する構造。
- APIキーや秘密情報がクライアントに露出する可能性のある実装。
- CSVを検証なしで即時登録する実装。
- 監査ログなしで重要データを更新する実装。
- 全画面を一律にクライアントコンポーネントへ寄せる実装。
- モジュール境界のない巨大な共通ディレクトリ。

## 画面・機能別の分類

| 画面・機能 | 分類 | 方針 |
| --- | --- | --- |
| ホーム/統計ダッシュボード | 再設計 | DB集計ベースで再構築し、カード表示やアクションアイテムの考え方は参考にする |
| メンバー管理 | 継承 + 再設計 | CRUD、検索、部署フィルタは継承し、DB/API/Auth対応で作り直す |
| メンバー詳細 | 継承 + 再設計 | スキル紐付け、ロール表示を継承し、スキル紐付けはメンバー自己申告とmanager承認・補正の流れへ再設計する |
| スキル管理 | 継承 + 再設計 | カテゴリ、レベル説明、CSV入出力を継承し、検証とDB永続化を強化する |
| ロール管理 | 継承 + 再設計 | スキルとレベルでロールを定義する考え方を継承し、判定ロジックをドメイン層へ置く |
| スキル検索 | 継承 + 再設計 | 特定スキルを持つメンバー検索を継承し、DB検索と権限制御を追加する |
| スキルマップ | 継承 + 再設計 | マトリクス表示の価値を継承し、パフォーマンスとレスポンシブ表示を改善する |
| CSV import/export | 再設計 | 初期対象は部署、メンバー、スキル、メンバースキルに限定し、プレビュー、検証、差分確認、監査ログを追加する |
| 通知 | 新規 | スキル申告、承認依頼、承認結果、差し戻しを通知する |
| AI評価 | 後続フェーズ | Phase 6で本番運用前提に再設計する |
| localStorage repository | 参考のみ | Repository抽象の考え方のみ参考にし、実装はPostgreSQL + Prismaへ置き換える |

## Phase別の扱い

| Phase | MVP要素の扱い |
| --- | --- |
| Phase 0 | MVPの継承/再設計/後続フェーズ分類を整理する |
| Phase 1 | MVPの型や画面を参考に、正式なドメインモデル、画面一覧、Mermaidによる主要フローを定義する |
| Phase 2 | MVPのlocalStorage実装は持ち込まず、PostgreSQL + Prisma基盤を構築する |
| Phase 3 | メンバー、スキル、ロール、スキル紐付け、ロール判定を再実装する |
| Phase 4 | スキル検索、スキルマップ、ダッシュボードをDB集計ベースで再構築する |
| Phase 5 | CSV、監査、権限を本番運用向けに強化する |
| Phase 6 | AI評価を本番運用前提で再設計する |
