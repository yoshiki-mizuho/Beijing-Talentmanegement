# 性能（性能改善 G の記録と守ること）

性能改善のフェーズ G（2026-11）で測ったこと、直したこと、これから守ることをまとめます。

## 測り方

- 本番ビルド（`npm run build` → `npm run start`）で、ADMIN・MANAGER・MEMBER の主な画面を3回ずつ開き、2回目以降の値を見る。
- 見る値は、表示までの時間（`load`）、DB の問い合わせの回数と合計時間、最初の HTML の大きさ。
- 問い合わせの回数は、計測のときだけ Prisma の `query` イベントを数える一時的な変更を当てて数える（コミットしない）。
- 人数が増えたときの様子は、架空の300人分のデータ（名前の先頭が `PERF-`、部署10、マネージャー30人、1人あたりスキル約15件、2年分のレベルの変更履歴 約1万3千件）をローカル DB に入れて測り、終わったら消す。
- この PC は DB が同じマシンにあるため、表示時間の差は小さく出る。社内サーバのように DB が別のサーバにある環境では、問い合わせの回数とデータ量の差が、そのまま待ち時間に効く。
- メモリが逼迫している PC では、関係のない画面まで遅くなり、数字が当てにならない。測るときは、ほかのサーバや作業を止めておく。

## 直したこと

| MR | 内容 | 主な効果 |
|---|---|---|
| G-1（!131） | 全画面に共通のレイアウトで、お祝いの演出（レベルアップ・ロール達成・応援・月のまとめ）を、出すものがないときに計算しない。同じ表示の中の重複した読み取りを React の `cache` で使い回す | どの画面も問い合わせが約6〜7割減（何も表示しない画面で 69→18 回） |
| G-2（!132） | ダッシュボードの重複した読み取りをまとめる。チーム目標の前の期間の実績を1回の取得にまとめる | ADMIN の個人ダッシュボード 159→50 回、MANAGER のチームダッシュボード 161→52 回 |
| G-3（!133） | メンバー一覧はサーバー側で絞り込み、1ページ（20件）と件数だけを返す。詳細は開くときに取る。スキルマップは保有者の一覧を、スキルを選んだときに取る | 300人で、最初の HTML がメンバー一覧 144→24KB、スキルマップ 93→20KB |
| G-4（!134） | 組織ダッシュボードは、レベルの変更履歴を集計が使う期間（直近12か月の推移の最初の月の初め以降）だけ読む。MANAGER は見える部署だけを読む。メンバーごとの `Map` にまとめてから集計する | 読む履歴の量が運用の年数に比例しなくなった。速さの測り直しは未実施（下の「残っていること」） |

## 採用しなかったこと

- **Prisma の `relationJoins`（試験中の機能）**：関連を1回の問い合わせで取るため、問い合わせは約65%減った。一方で、ロール達成の演出の E2E が不安定になった（3回に1回失敗し、所要時間が約6倍）。原因を特定できなかったため採用しない。

## これから守ること

- **レイアウト（`src/app/(app)/layout.tsx`）は軽く保つ**。全画面で毎回動くので、重い読み取り（成長データ、バッジの材料、月のまとめなど）を直接呼ばない。演出などは「出すものがあるか」を軽い問い合わせで先に確かめ、あるときだけ中身を読む。
- **React の `cache` を付けてよいのは、引数が同じなら結果が同じ読み取りだけ**。書き込みの後に読み直す必要があるもの（server action の中など）には使わない。今付けているのは、成長データ、バッジの材料、ロール達成、担当範囲、月のまとめ。
- **人数に比例するデータを、最初の HTML に全部入れない**。一覧はサーバー側で絞り込んでページで返し、詳細は開くときに取る。
- 基盤の氏名で検索・並べ替えする一覧は、権限範囲と DB 条件で候補を絞った後、表示プロフィールを一括取得してアプリ内で検索・並べ替えし、20件単位でページ分割する。プロフィールは1人ずつ取得しない。
- **履歴を読むときは、使う期間だけを読む**。集計の期間を変えるときは、読む期間の始まりも合わせて直し、「それより古いデータを足しても結果が変わらない」単体テストを更新する。
- **メモリの中で同じ配列を何度もなめない**。メンバーや部署ごとに `Map` にまとめてから使う。

## 残っていること

- G-4 の速さの測り直し。2026-11-16 の計測は PC のメモリが逼迫していて無効だった。メモリに余裕があるときに、300人の架空データで測り直す。
- MEMBER の個人ダッシュボードは、成長データ・バッジ・月のまとめ・チームのレベルアップの各読み取りが関連をそれぞれ読むため、問い合わせが約110回残っている。減らすには読み取りの組み直しが要るので、社内サーバで実際の遅さを見てから判断する。
