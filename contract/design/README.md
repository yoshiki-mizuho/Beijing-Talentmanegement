# 画面の見た目の決まり

どの Hub の画面も同じ製品群に見えるようにするための決まり。値は、Reporthub の今の画面のコードから取った実際の値。

基盤が配るのは「決まり」まで。画面の枠組み（React、Vue、素の HTML など）と中身は、各 Hub が決める。共通の部品（ヘッダなど）は配っていない。

## 入っているもの

| ファイル | 中身 |
|---|---|
| `tokens.css` | CSS の変数（`--hub-*`）だけ。色、文字、余白、角の丸み、影、枠の寸法、重なりの順、動き |
| `layout.md` | 枠の決まり。ヘッダ・左のナビ・本体・狭い画面・デスクトップ版の殻の中 |
| `components.md` | 基本の部品の見た目。ボタン、入力欄、カード、バッジ、表、空の状態、読み込み中、トースト、ダイアログ |
| `example.html` | `tokens.css` だけを読み込んで、枠と部品を素の HTML + CSS で組んだ見本。ブラウザでそのまま開ける。写して使ってよい |
| `sources.md` | 変数ごとの、Reporthub のコードでの出どころ。基盤の担当が、値を直すときに使う |

## 使い方

1. Hub のリポジトリで `scripts/update-contract.sh <版>` を流す。`contract/design/` に写しが入る。コミットする。
2. 画面で `contract/design/tokens.css` を読み込む（自分のアプリから配る。ビルドに取り込んでも、そのまま配ってもよい）。
3. 色・文字・余白・寸法は、変数（`var(--hub-...)`）で書く。枠は `layout.md`、部品は `components.md` のとおりに作る。迷ったら `example.html` の CSS を写す。
4. `example.html` と自分の画面を、幅 1366 × 高さ 768 で並べて見比べる。

Tailwind CSS などで自分のテーマを持つときは、テーマの値を `var(--hub-...)` にする。書体のファイルは入っていない。Inter と Noto Sans JP を、自分のアプリから配る（配らないと、PC の書体で出る）。

## 守ること・自由なこと

| | 守ること（共通） | 自由なこと（製品ごと） |
|---|---|---|
| ヘッダ | 高さ、地、区切り、並べ方。左に製品の印と名前、右端に本人のメニュー | 中央と右に置くもの（検索、通知、新しく作るボタンなど）。本人のメニューの項目（ログアウトのほか） |
| 左のナビ | 幅、項目の大きさ、状態ごとの見た目、アイコンの大きさと線 | 項目と順番、アイコンの絵 |
| 本体 | 色（主の色を除く）、文字、余白、角の丸み、影。基本の部品の見た目 | 何を置くか、画面の構成。主の色（下の「主の色」） |
| 値 | `tokens.css` の変数を使う。写しを書き換えない | 変数に無い値が要る場面（図やグラフの色など）は、Hub が決める |

### 主の色

製品を見分けられるように、主の色だけは製品ごとに変えてよい。

- 上書きしてよいのは `--hub-color-primary-50`〜`950` の 11 段と `--hub-color-text-on-primary` だけ。役割の変数（主ボタン、リンク、フォーカスの輪、選択中の地と文字）は、この 11 段を指しているので、書き換えなくても揃う。
- 自分の CSS の 1 か所に、`tokens.css` の後で `:root { --hub-color-primary-50: …; … }` と書く。`tokens.css` の写しは書き換えない。
- 11 段は、明るさの並びを `tokens.css` と揃える（50 が一番明るく、950 が一番暗い）。
- 主ボタン（`--hub-color-primary-600` の地に `--hub-color-text-on-primary` の文字）のコントラスト比を 4.5:1 以上にする。

値が足りない・変えたいときは、Hub の側で値を作らず、基盤のリポジトリ（`chosen-ryoiki-group/hamburg/hub-platform`）に issue を出す。

## 文言と振る舞い

| 決まり | 内容 |
|---|---|
| 文言 | ビジネスニュートラル。あおる言い方・なれなれしい言い方をしない |
| 配色 | 明るい配色だけ。ダークモードは作らない |
| 動き | 動かすのは、読み込み中の表示（帯の明滅、ボタンの輪）と、色の変わり目だけ。注意を引くための点滅は使わない |
| 新着・未読の印 | 小さな点か、件数の丸で出す（`layout.md` §2.1 / §3.1）。文字のバッジを足さない |
| フォーカス | キーボードで移ったときに、輪を出す |
| ブラウザ | 最新の Chrome / Edge / Safari / Firefox で動くこと。デスクトップ版の殻のために画面が守ることは `layout.md` §6 |

## 値を直すとき（基盤の担当）

元は Reporthub の画面（`tokyo/reporthub` の `pgm/frontend`）。Reporthub の画面の共通の見た目（`src/app/globals.css`、`src/components/organisms/layout/`、`src/components/atoms/`、`src/components/molecules/`）を変える MR を出すときは、ここも同じ時に直す。

1. `sources.md` で、変えた class を使っている変数を探す。
2. `tokens.css` の値と、`sources.md` の出どころを直す。見た目の決まりが変わるなら、`layout.md` / `components.md` / `example.html` も直す。
3. `sh ci/checks/check-design.sh` を通す（CI でも流れる）。`example.html` を幅 1366 × 高さ 768 で開いて、Reporthub の画面と見比べる。
4. `contract/CHANGELOG.md` に足し、マージ後に版のタグを打つ。変数の名前を変える・消すのは、互換を壊す変更（利用ガイド §11.4 の 3 段で行う）。
